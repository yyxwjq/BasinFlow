# TS 侧不是流匹配：根因、证据与修复（2026-09-13）

用户发现：**R+P→TS 的过渡态是一步求解的，这根本不是流匹配模型。** 本文件记录
逐行证据、根因、修复内容与验证方式。R→P 侧本轮不动（其 `t = 0` 是 `docs/22`
的既定诊断结论），只修 TS。

## 一、修复前的实际算法（逐行证据）

```ini
# configs/0910/transition1x_ts_equivariant.ini（修复前）
[init]
flow_time = 0.0        # 把训练时间钉死在 0
source_scale = 0.0     # 源是确定的中点桥
[evaluation]
eval_num_steps = 1     # 采样只有一步
```

```python
# basinflow/data/pyg.py（修复前）
time = self._flow_time(index)          # time_distribution="fixed" → 恒为 0.0
pos = (1.0 - time) * midpoint + time * state.positions   # t=0 时 pos == midpoint
target_velocity = state.positions - midpoint
```

```python
# basinflow/evaluation/transition_state.py（修复前）
for step in range(int(num_steps)):            # num_steps = 1
    output = model(batch, t=step / float(num_steps))   # t = 0.0
    positions = positions + velocity / float(num_steps)  # source + v
```

三条合起来：训练时**每个样本都是** `x_t = (R+P)/2`、`t = 0`，监督
`v = TS − (R+P)/2`；采样时一次前向加回源几何。等价于让网络拟合
`f(R, P) = TS − (R+P)/2`——**直接回归**。它没有速度场（t 只在单点被监督，
其余 t 处无定义）、没有积分、没有时间维度。`eval_num_steps` 即使设成 50 也没用：
第一步就吐出全部位移，后续步骤只是对同一个 t 的重复查询。

**为什么之前没被发现**：`docs/23` 记录了这条臂是"1 步直接回归（`flow_time = 0`，
与 R→P 最优臂一致的参数化）"，当时是被当成**有意选择**写下来的，而 R→P 的
`docs/22` 用 875 行论证了"`t = 0` 直接回归优于带泄漏的插值"。两篇文档各自自洽，
合起来就掩盖了"TS 根本没有场"这件事。

## 二、根因

单一根因：**`[init] flow_time = 0.0` 把训练时间分布退化成单点**，
`time_distribution = beta` 形同虚设（配置里写了 beta，但被 `flow_time` 覆盖）。
第二个根因是 `source_scale = 0.0` 让源成为确定点，于是连"从分布到分布的传输"
都不存在。

流匹配的两个必要条件因此都不成立：

| 必要条件 | 修复前 | 后果 |
|---|---|---|
| 时间在区间上有分布 `t ~ p(t)` | `t ≡ 0` | 场只在单点有定义，积分无意义 |
| 源是分布 `x0 ~ p0` | `x0 ≡ (R+P)/2` | 没有"输送"，只有一对一映射 |

## 三、修复（B2：MolGEN 式随机源 + 全 t 监督）

变分路径（`v` 沿路径为常数，与 MolGEN 的 `Linear` path 一致）：

```text
x0 = (R + P) / 2 + sigma * xi        sigma = 1.0 A   (MolGEN: randn_like(x1) * x0std)
t  ~ Beta(0.8, 0.8)                                 (MolGEN: transport.py:265)
x_t = (1 - t) * x0 + t * TS
v   = TS - x0
```

`sigma = 1.0` 是 MolGEN 的 `x0std`。它同时解决 `docs/22` 记录的"代数反演"泄漏：
`x_t` 在 t>0 时不再能反解出 `TS`（因为源本身带 1 Å 噪声），所以网络必须学输送
而不是学逆运算。

### 采样与训练的语义一致性

训练在 `t ~ Beta(0.8,0.8)` 上监督；采样是 ODE 积分，用 `t = 0, 1/N, ..., (N-1)/N`
的均匀网格查询同一个场。这是标准做法：训练分布塑造**场**，采样网格只是**积分器**。
两者一致性由 §四 的"场非平凡"测试保证（位置确实沿路径变化，而不是永远查询 `x0`）。

#### 决定性诊断：把源换回确定桥后仍然不达标

用**同一个 epoch-10 checkpoint**，只把采样起点换成确定性中点桥（σ = 0，即

|---:|---:|---:|---:|---:|

即：**在最优起点、也已积分收敛的情况下，这个场仍然给出 0.856 Å，低于修复前
直接回归臂的 0.230 Å，也低于桥基线 0.487 Å（越差越好 → 这里是"更高更差"）。**

#### 根因：场学会了"欠移动"（contraction）

在确定性桥上（t = 0）逐事件比较模型输出与真值（全 val）：

| 量 | 数值 |
|---|---:|
| 训练目标信噪比（rms，`\|TS−mid\|` / `σ`） | **2.86**（信号 2.855 vs 噪声 0.996） |
| 每原子目标位移范数 | 3.753 Å |
| 每原子预测位移范数 | 2.429 Å |
| **收缩比** | **0.648** |
| 分量 L1 误差 | 1.556 Å（对应训练 loss 0.74） |

结论：σ = 1.0 时**训练目标的信噪比并不差（2.86）**，所以问题不是"目标被噪声淹没"，
而是网络在覆盖 1 Å 噪声源的整个分布后，输出的是**条件均值**而非逐样本位移：
预测幅度只有真值的 65%，于是即便从最优起点出发也只能走到桥与 TS 之间。
`docs/22` 的"代数反演"担忧在此不适用——t=0 处根本不存在反演问题——真正的代价是
**把 σ 开大换来反演安全性，却把回归目标变成了"平均场"**。

### 五之四 · 下一步（B3：小噪声源）

按用户已选的 B2 结论，σ = 1.0 的输送代价过高。建议改用 B3：

```text
source_scale = 0.2        # 信号/噪声比 ≈ 14，网络能学到逐样本位移
time_distribution = beta  # 仍是真流：t 有分布、场可积分、多步有意义
eval: 从 x0 = mid + 0.2*xi 出发，16 步 ODE，best-of-N 才有意义
```

理由：

1. **避免平均化**：σ = 0.2 时目标信噪比 ≈ 14（σ = 0.1 时 ≈ 29），网络不必在
   宽分布上取均值；
2. **仍然没有反演泄漏**：采样从 **t = 0** 起步，而 t = 0 处的目标是
   `x1 − x0`，与源的噪声无关；反演风险只出现在"在 t>0 处查询网络"，我们的采样
   网格虽然包含 t>0，但场在那里已被 `x_t` 约束为同一常数，不会给出 `(x_t−x_0)/t`；
3. **best-of-N 仍成立**：源仍有随机性（0.2 Å），不同 trial 是不同样本。

对照基线（必须打败）：中点桥 0.487 Å；修复前直接回归臂 0.230 Å。B3 若落在
**< 0.35 Å** 即可认为"真流匹配 + 多步积分"在本任务上不输直接回归，同时拿到了
随机源、可积分的场与 best-of-N 语义。

### 六之四 · 根因：常速度路径 + L1 ⇒ 一步映射，不可积分

变分路径 `x_t = (1−t)x_0 + t·x_1` 的切向量是 `x_1 − x_0`，**与 t 无关**。于是：

1. 训练目标在整个 t 区间上**恒为同一个常向量**；模型只需输出"每个原子的位移向量"，
   不需要学 `v(x, t)` 的 t 依赖；
2. 采样时 16 步各查一次，得到的是**同一个常向量**，累计位移 ≈ 16 × 3.7 Å ≈ 59 Å，
   而实际需要 2.87 Å → **第 2 步起就已在训练流形之外**；
3. 流形之外的输出由 `(current − reference)`、`(endpoint − current)` 这些**位置相关**
   的特征决定，于是方向翻转、来回震荡（§六之一 的过冲-回摆）。
4. 实测 t 响应就是这个预言：`|v_pred| ≈ 3.2–3.7 Å` 在 t = 0…1 上**近似常数**
   （B3 在 t=0 为 3.22，t≥0.2 后稳定在 3.66–3.71），正是"常速度场"的签名。

结论：**这不是"流匹配学不会"，而是"用常速度路径把一步映射包装成了流"。**
B2/B3 唯一的真流内容（t 有分布、源是分布）不足以产生可积分的场，因为场的
t 依赖被路径本身抹掉了。修复前的"一步"并非实现疏漏，而是这个参数化的
**数学后果**——这也解释了为什么当初把它写成 `eval_num_steps = 1` 竟然没有立刻暴露。

| 方案 | 改动 | 为什么可行 | 成本 |
|---|---|---|---|
| **X1-prediction**（推荐） | 训练目标从 `v = x1 − x0` 改为直接回归 `x1`（即 `target_pos`），采样时用 `v = (x1_pred − x_t)/(1 − t)` 积分 | 标准 flow-matching 做法；路径可自限，t = 1 处分母虽发散但 `x1_pred → x_t`，场自然收敛；梯度数值稳定（文献有现成处理） | 改 loss 与采样，重训 10 epoch ≈ 1.8 h |
| **衰减路径** | 保留速度预测，改路径为 `x_t = cos(πt/2)·x0 + sin(πt/2)·x1`，此时真值为 `(π/2)(cos·x1 − sin·x0)`，t=1 处自动趋零 | 最标准的 flow matching：常速度病态消失，多步积分稳定 | 改数据集与采样，重训 |

两者都必须重训。**推荐先做 X1-prediction**：它不需要新路径，改动最小，且直接
对齐 OA-ReactDiff 的 x0-prediction 思路。

### 六之六 · 与论文口径的关系（本轮未做）

这些数字**不能**与 OA-ReactDiff/MolGEN 的 0.058/0.076 Å 并列：他们允许镜像
（`ignore_chirality=True`）、截断 1 Å、并用 40 次采样 + 置信度筛选。按
`docs/17_reference_protocol_audit.md`，正式对比必须双口径同时报告，且需要
confidence 模型（本机无 checkpoint）。本轮所有数字都是**严格口径 + 单次采样**。

## 七、已知遗留

- **R→P 未改**：其 `flow_time = 0.0` 是 `docs/22` 的既定结论，本轮按用户指示不动。
  它同样是"直接回归 + 多步空转"（16 步里只有第一步在做事），是否需要改成真流匹配
  需另行决定。
- **TS 仍未达到可用精度**：B2/B3 都停在 0.9–1.0 Å，差于桥基线 0.487 Å。必须先按
  §六之五 修参数化并重训，任何下游对比（论文口径、R→P 联动）在此之前都没有意义。
- **`best-of-N` 的语义变了**：修复后源带噪声，不同 trial 是不同的随机源，所以
  `best-of-N` 与 `one-shot` 的差别是**真实的采样方差**；修复前它们只是同一输出的重复。
- **未重训完整轮次**：本文件只覆盖 10 epoch 探针；正式对比前需按 §六之五 的决定
  重训并决定 epoch 预算。
