# Code Review: 2026-07-03

## Review Scope

This review covers the full repository surface available in this checkout:

- `src/basinflow`: data records, dataset loading, collation, geometry, graph
  construction, seeds, flow targets, models, sampling, training, and
  benchmark helpers.
- `tests`: unit, integration, optional dependency, optional real-data, and
  end-to-end smoke tests.
- `examples`: user-facing data and Stage 3 walkthrough scripts.
- `tools`: EON `.con` to multi-frame event conversion.
- `README.md`, `pyproject.toml`, and `docs`.

Environment assumption: local development and verification should run in
the conda environment `ifdiff`, as declared in
`docs/08_technical_stack.md`.

## Executive Assessment

The repository is a coherent Stage 3 prototype.  The main architecture is
sound: data parsing, basin-level grouping, PBC-aware geometry, seed
contracts, product-flow targets, EGNN sampling, and no-relaxation recall
are separated into small modules.

The main engineering risks were not broad architecture problems.  They
were interface semantics, reproducibility, and entrypoint ergonomics:

- Stage 3 used `active_mask` as both model input and supervision label.
- `EventDataset.subset()` did not preserve requested basin order.
- Split assignments were not persisted.
- `tools/eon_to_events.py` required saddle files even though TS frames are
  optional in the schema.
- `examples/demo_pipeline.py` assumed `basin "0"` and `event_0`.

These issues are now fixed or documented as follow-up work.

## Source Review

### `src/basinflow/data`

- `records.py`: clear dataclass boundaries and useful ASE round-trip
  support.  The `movable_mask` contract is well documented and enforced.
  Future improvement: add serialization helpers when full dataset
  manifests are introduced.
- `raw_events.py`: loader behavior matches the three-frame event schema
  and preserves CSV metadata.  Current event id policy remains filename
  stem; this is documented in `docs/issues.md`.
- `dataset.py`: pairwise and basin views are simple and readable.  Fixed:
  `subset()` now preserves requested basin order.  Added minimal JSON
  split manifest save/load for reproducible splits.
- `collate.py`: variable-size batching is practical and dependency-light.
  The PyG bridge remains optional and data-level `active_mask` remains a
  label field, not a model input field.

### `src/basinflow/geometry` and `src/basinflow/graphs`

- `mic.py`: MIC utilities are compact and tested for molecule, PBC, mixed
  PBC, translation, rotation, and permutation behavior.  Removed a
  temporary review comment.
- `neighborlist.py`: ASE-backed graph construction is appropriate for
  Stage 3.  Future improvement: add stricter tests for non-orthogonal
  cells before relying on production periodic benchmarks.
- `torch_graph.py`: keeps torch optional and rebuilds graphs from dynamic
  positions.  `basinflow.geometry` now exposes torch graph builders through
  lazy loading so importing core graph utilities does not require torch.

### `src/basinflow/inits` and `src/basinflow/flow`

- `inits/records.py`: `EventSeed` correctly represents scalar/vector/
  geometry seed roles and prevents fixed-atom motion.
- `inits/generators.py`: zero, Gaussian movable, and product displacement
  seeds are enough for Stage 3 smoke tests.  Future seed types should
  stay physically interpretable and not become metadata-only prompts.
- `flow/targets.py` and `flow/torch_batch.py`: fixed the key semantic
  issue.  Flow items now expose `active_prior` as model input and
  `target_active_mask` as supervision.  The ambiguous flow-level
  `active_mask` key has been removed.

### `src/basinflow/models`, `sampling`, `training`, `benchmark`

- `models/product_event_flow.py`: minimal and dummy models are useful for
  contract tests.  They should remain smoke-test models, not research
  baselines.
- `models/egnn_product_flow.py`: Stage 3 EGNN is intentionally compact.
  Fixed: forward pass no longer requires target active labels; loss uses
  `target_active_mask`.  Future improvement: introduce a config object
  before adding stronger backbones.
- `sampling/candidate_sampler.py`: sampler now builds inference batches
  with `active_prior` only.  It preserves fixed atoms during integration
  and rebuilds dynamic graphs at the configured interval.
- `training/product_flow.py`: readable single-epoch loop and checkpoint
  payload.  Future improvement: include split manifest path and git state
  in checkpoint metadata.
- `benchmark/basin_recall.py`: useful no-relaxation prototype.  Its
  metrics must be described as geometric candidate recall, not validated
  KMC event recall.

## Tests Review

Tests cover the intended contracts well for a prototype:

- Data/records/raw event loading tests cover two-frame and three-frame
  events, basin grouping, move masks, FixAtoms, and optional real Au data.
- Geometry tests cover MIC, active labels, directions, invariance, and PBC
  graph offsets.
- Stage 3 tests cover flow target construction, torch conversion, EGNN
  forward/equivariance/toy overfit, training, candidate sampling, and
  no-relaxation recall.

Added regression coverage:

- `active_prior` versus `target_active_mask` semantics.
- Sampler inference batches without target active labels.
- Ordered subset behavior and split manifest round-trip.
- EON conversion with optional saddle frames.
- Demo execution without `event_0` or numeric basin ids.

## Examples and Tooling Review

- `examples/demo_pipeline.py`: now runs directly from the source tree and
  no longer assumes Au-specific ids.  It remains a Stage 1-2 data demo.
- `examples/e2e_stage3.py`: good Stage 3 smoke walkthrough.  Future
  improvement: mirror the direct source-tree import fallback used by
  `demo_pipeline.py`.
- `tools/eon_to_events.py`: fixed to allow two-frame events.  Future
  improvement: revisit integer-only basin folder detection before adding
  a second benchmark system.

## Recommended Next Refactors

1. Add experiment summaries around split manifests: model config,
   sampling config, checkpoint id, and metric JSON.
2. Add a small config layer for Stage 3 training/sampling to avoid
   hard-coded example settings.
3. Add non-orthogonal-cell graph tests before claiming broad crystal
   robustness.
4. Add a second benchmark dataset with more than one movable atom before
   increasing model complexity.
5. Keep Stage 4 TS flow separate from the Stage 3 product/event proposal
   code path.
