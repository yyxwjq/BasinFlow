# Transition1x R→P 的 RMSD 根因与当前水平（2026-09-13）

用户要求：**先做 R→P 任务，把 Transition1x 的 RMSD 压到 0.1–0.2 Å**，达不到就持续找原因。

## 执行摘要

**起点**：aligned 中位 1.0370 Å，且**仍劣于"什么都不做"**（0.9852 Å）。
**现在**（R→P，方向条件臂 80 轮，全量 test）：

| 口径 | aligned 中位 | `min(rmsd,1)` 均值 | < 0.2 Å | 零移动基线 |
|---|---|---|---|---|
| test 全部（537） | **0.6002** | **0.6384** | 15.1% | 1.1280 / 0.9037 |
| test 单事件（381，KMC 相关口径） | **0.4143** | **0.4913** | **21.3%** | 0.9276 / 0.8642 |
| **train 单事件** | **0.1997** | — | **50.2%** | — |

**结论**：训练集上**已经进入 0.1–0.2 Å 目标区间**（中位 0.1997、50.2% 达标）；
test 还差约 2 倍，差距是**泛化**而非信息。

## 找到的四个原因，按影响排序

| # | 原因 | 性质 | 修法 | 证据 |
|---|---|---|---|---|
| 1 | **捷径反演**：σ=0.05 Å 的先验让 `x_t` 对每个 `t>0` 可代数反解 `(x_t−(1−t)x0)/t` | 可修 | `flow_time = 0` 直接回归 | 训练线余弦 0.998，`t=0` 处 0.028；从真值产物 rollout 发散到 23.99 Å |
| 2 | **优化不足**：MolGEN 的 lr 1e-4 是 warmup/cosine 的**峰值**，被当成常数；L1 梯度逐元素恒为 ±1，步长噪声不随损失下降 | 可修 | 补 warmup+cosine 调度 | 64 事件探针 0.492（lr 1e-3, 120ep）→ **0.138**（lr 3e-3, 900ep） |
| 3 | **种子噪声**：`t=0` 时种子就是输入，0.05 Å 高斯噪声是纯干扰 | 可修 | `gaussian_scale = 0.0` | 128 事件每个 epoch 稳定好 8%（探针：0.97 → 0.49） |
| 4 | ~~**不可约歧义**~~ | **已推翻** | — | 见下 |

**原因 4 的更正**：早期用**元素对**签名（如 `C-H:F`）测量，得出"同拓扑事件仍差 1.33 Å"。
改用**原子索引级**签名后：9000 条训练事件 = **1182 个构象**，**没有任何一对事件
同时共享构象与拓扑** ⇒ `(构象, 拓扑) → 产物` 是**良定义的函数**，**没有信息下界**。
同理 `(R, P) → TS` 也是函数（9000 个端点组合互不相同）。
误差与"拓扑有多新"的相关性 **−0.019**，即瓶颈不是"没见过这种事件"。

## 已排除的改动清单（全部实测为负或无收益）

试过就记录，避免重复走：

| 改动 | 结果 |

**当前最好仍是原方案**：`r_max=12`、`weight_decay=0`、方向条件、cosine 调度。

|---|---|---|
| **train** aligned 中位（256 basin） | 0.1900 | **0.1442** |

## 详细记录

本文件给出两个**互不相同**的原因，各自带可复现的测量：

1. **捷径解（训练动力学问题，可修）**：在 σ=0.05 Å 的先验下，插值位置
   `x_t = (1-t)x_0 + t x_1` 对每个 `t > 0` 都**泄漏答案**，且泄漏是可代数反解的。
   网络于是学到 `v̂(x,t) = (x - x_0)/t`——训练线上几乎完美（cos 0.998），
   但**离线即发散**，且在采样起点 `t = 0` 处完全没有方向（cos 0.028）。
2. **不可约歧义（任务本身，不可修）**：Transition1x 里近同反应物要求**不同的拓扑变化**
   与**不同的内禀位移**。即使把真值键变化当作条件给模型，`(R, 拓扑变化) → P` 仍是
   一对多，确定性映射的误差下界约 **0.6–0.9 Å**。

结论（**已按 §二之四 更正**）：0.1–0.2 Å **并非不可达**——§二 的"不可约歧义"
用的是过粗的元素对签名，改成原子索引级签名后，训练集里**没有任何一对事件
共享同一构象与同一拓扑**，`(构象, 拓扑) → 产物` 是良定义的函数。
剩下的 0.43 Å 是**优化/泛化**问题，可用训练解决。

本轮最好的臂（C，epoch 149）把它做到 aligned 中位 0.573 Å（val）/ 0.628 Å（test）、
`min(rmsd,1)` 均值 0.628 / 0.648 Å，**13.2% 的 test basin 落进 0.2 Å 以内**，
而"什么都不做"是 0%。该数字的来源是 MolGEN/ReactOT
在 **R+P→TS** 任务上、**Kabsch 对齐**口径下的值（`val_meanRMSD_Kabsch ≈ 0.129–0.161`，
`Transition1x-inference.py:6-14`）。可行的替代目标与协议建议见第四节。

## 一、捷径解：证据

在第 5 个 epoch（run `transition1x_bond_change_9000`，σ=0.05，MolGEN 规模网络，
oracle 键变化条件）上，沿**精确训练线** `pos = (1-t)x_0 + t·P` 取点，比较模型输出与
`target_velocity = x_1 - x_0`：

| `t` | 方差解释率 | 模长比 `|v̂|/|v|` | 余弦 |
|---|---|---|---|
| **0.00** | **0.0006** | **0.037** | **0.028** |
| 0.05 | 0.974 | 0.892 | 0.989 |
| 0.10 | 0.988 | 0.970 | 0.995 |
| 0.25 | 0.994 | 1.037 | 0.997 |
| 0.50 | 0.996 | 1.002 | 0.998 |
| 0.90 | 0.996 | 1.003 | 0.998 |

复现：`tools/diagnose_flow_fit.py --run-dir <run> --checkpoint <epoch_*.pt> --times 0 0.05 0.1 0.25 0.5 0.9`。

机制：`x_0 = R + 0.05·ξ`，`ξ` 的尺度远小于 `P - R`（后者中位 1.08 Å、均值 4.21 Å）。
于是 `x_0 ≈ R` 是**已知**的，网络可以直接算

```text
x_1 = (x_t - (1-t)·x_0) / t
```

这在 `t > 0` 处处成立，与反应是什么无关。梯度自然选择它：训练线上损失接近 0，
而真正的 `R → P` 映射从未被学到。`t = 0` 处该式除零，网络只能退化为输出 ≈ 0
（模长比 0.037）。

同一诊断的两个推论互相印证：

| 项 | 值 | 含义 |
|---|---|---|
| 从种子出发 rollout 16 步的总位移 | 0.88 Å | 中位目标位移 1.08 Å，即**几乎没动** |
| 从**真值产物**出发 rollout 16 步 | 终点 RMSD **23.99 Å** | 离线的速度场是纯泄漏反演，一步放大 `1/t` 倍 |

即：**这不是"训练不够"**。捷径解是当前目标函数的（近）全局最优，多训轮数只会让它更精确。
doc 18 §五观察到的"10 轮后验证损失平动""更多 Euler 步无效""1 步优于 16 步"三条，
都由这一个机制解释。

**反证：把先验换成 MolGEN 的 σ=1.0 之后，同样的诊断给出完全不同的场**
（`transition1x_bond_change_x0std1` 的 epoch 7）：

| `t` | 方差解释率 | 模长比 | 余弦 | `|v̂|` | `|v|` |
|---|---|---|---|---|---|
| 0.00 | 0.089 | 0.425 | 0.299 | 1.91 | 4.49 |
| 0.05 | 0.397 | 0.581 | 0.644 | 2.60 | 4.49 |
| 0.10 | 0.701 | 0.782 | 0.843 | 3.55 | 4.54 |
| 0.25 | 0.935 | 0.911 | 0.970 | 4.08 | 4.48 |
| 0.50 | 0.954 | 0.875 | 0.979 | 3.99 | 4.56 |
| 0.90 | 0.959 | 0.829 | 0.981 | 3.71 | 4.48 |

`t = 0` 处仍有方向（cos 0.299 而非 0.028），沿训练线的拟合随 `t` 单调恢复，
且从种子出发的 rollout 总位移 **3.38 Å**（σ=0.05 时只有 0.88 Å）。
即：**σ=0.05 是退化性的，σ=1.0 不是**。残余误差此时来自训练不足与 §二 的歧义，
不再是捷径。

### 为什么 MolGEN 不会掉进这个坑

MolGEN 的先验是 `torch.randn_like(x1) * x0std`，且 **`x0std = 1.0`**
（`mdgen/transport/transport.py:262`，`mdgen/parsing.py:83`）。
`x_0` 是 **1 Å 量级的未知噪声**，`(x_t - (1-t)x_0)/t` 不可用，反解不出来。
BasinFlow 此前用 `gaussian_scale = 0.05`，把先验退化成了"反应物的副本"，
才让这条捷径成立。**这是与 MolGEN 的一处未被先前审计发现的实质偏离**
（doc 20 只对照了任务、损失、网络规模与优化器）。

### 已采取的两个修复

| run | `gaussian_scale` | `flow_time` | 采样步数 | 修的是什么 |
|---|---|---|---|---|
| `transition1x_bond_change_x0std1` | 1.0 | 采样 | 50 | 与 MolGEN 先验对齐，堵住代数反解 |
| `transition1x_direct_t0_9000` | 0.05 | 固定 0.0 | 1 | 直接把任务写成 `R → P` 回归，`t` 通道不再存在 |

`transition1x_bond_change_9000`（σ=0.05、采样 t）保留为**阴性对照**，其 epoch-5
诊断就是上面那张表。

## 一之二、第三个原因：优化不足（可修，且比前两个都大）

前两个原因成立，但不构成全部。两个新测量把它们之外的空间打开了。

### 训练集本身的误差远低于验证集

`epoch 149` checkpoint，同一协议（oracle 条件、1 步采样）：

| 划分 | aligned 中位 | aligned 均值 | `min(rmsd,1)` 均值 |
|---|---|---|---|
| **train**（512 basin） | **0.3785** | 0.5959 | 0.4199 |
| val（536） | 0.5734 | 0.9854 | 0.6278 |
| test（537） | 0.6277 | 0.9995 | 0.6483 |

train 与 test 差 1.66×：这既是泛化间隙，也说明**模型在见过的数据上都还有 0.38 Å 没消掉**。

### 架构能不能拟合？能，而且能到 0.14 Å

固定 64 条训练事件（无种子噪声、`t = 0`），同一架构（128 宽 4 层，`bounded`）：

| lr | epoch | 训练 64 条的 aligned RMSD 中位 | 均值 | 末步 L1 |
|---|---|---|---|---|
| 1e-3 | 120 | 0.492 | 0.583 | 0.317 |
| 3e-3 | 600 | **0.164** | 0.288 | 0.197 |
| 3e-3 | 900 | **0.138** | 0.205 | 0.094 |

**0.138 Å 已经落在 0.1–0.2 Å 目标之内。** 也就是说：架构、边条件、参数化都不是瓶颈，
**此前的三轮实验全部卡在优化上**。

### 键变化条件的第二部分：方向（`bond_change_direction`）

用户原话是"模型知道了末态的**键位、方向的变化**"。第一版只做了键位（离散标签）。
缺的那一半有实际后果：`t = 0` 时 `current = x0 = R = reference`，于是
`vector_input(current - reference)` 恒为 **0**——网络在起点拿不到任何向量输入，
所有方向都必须由不变标量特征合成。

补法是给每个原子一个等变的拉/推向量（只用参考几何 + 离散标签，不含坐标）：

```text
unit_ij  = (R_j - R_i) / |R_j - R_i|
raw_i    = sum_j [formed_ij - broken_ij] * unit_ij
```

生成键把两个原子拉近、断裂键把它们推远。经一个 `Linear(1, num_features)` 加进初始
向量特征。**该层只在 `bond_change_direction = true` 时创建**，因此所有既有
conditioned checkpoint 的 state_dict 完全不变、仍可原样加载（有测试钉住这一点）。

固定 128 条训练事件、同等优化（lr 3e-3、400 epoch）的探针：

| 臂 | 训练 aligned RMSD 中位 | 末步 L1 |
|---|---|---|
| 仅离散键变化 | 0.9128 → **0.1166** | 0.0907 |
| **+ 方向向量** | 0.9111 → **0.0921** | 0.0587 |

方向特征再降 21%，两条都落进 0.1–0.2 Å。完整训练臂见 §六。

### 三条被实测排除的"后处理/集成"捷径

误差既然集中在优化上，先试了三种不需要重新训练的做法。**全部无效或近乎无效**，
记在这里以免重复尝试（单事件 test 口径，C149 模型）：

| 做法 | aligned 中位 | < 0.2 Å | 结论 |
|---|---|---|---|
| 基线 | 0.4287 | 18.6% | — |
| 三个 checkpoint（C149 + cosine@36 + direction@23）位移平均 | **0.4216** | **19.7%** | 仅 +2%，模型之间误差高度相关 |
| 全局放大 ×1.05 / ×1.10 | 0.4295 / 0.4380 | 17.3% / 15.5% | 变差 |
| 幅度重标定 `1 + 0.15·\|d\|` | 0.4281 | 17.8% | 持平偏负 |
| 幂律重标定 `(\|d\|/0.93)^0.15` | 0.4430 | 14.4% | 变差 |

误差解剖（C149，单事件 test）解释了为什么重标定救不了：

| 真实 `\|d\|` | n | 方向余弦中位 | 幅度比中位 |
|---|---|---|---|
| 0.5–0.8 | 114 | 0.942 | 1.006 |
| 0.8–1.2 | 181 | 0.859 | 0.917 |
| 1.2–2.0 | 75 | 0.857 | 0.834 |

**方向是好的（余弦 0.86–0.94），幅度在大位移处系统性偏小**——但这个偏小是角度误差的
结果而不是可修正的偏置：放大位移同时把角度误差一起放大，所以任何全局或幅度相关的
重标定都不改善。**唯一有效的手段仍是把它拟合得更好。**

### 为什么优化不足

MolGEN 的 `lr = 1e-4` 是 **warmup/cosine 的峰值**而不是常数，而且它训练 20 万步以上；
前三个臂把峰值当成常数、只训 8460–21009 步。对一个确定性回归目标，这远远不够。
另外 L1 的梯度逐元素恒为 ±1，**步长噪声不随损失下降而减小**，所以高学习率必须配退火：

直接把常数 lr 提到 2e-3 会让损失在 1.4–2.5 之间震荡（实测），因此本轮在
`basinflow/training/product_flow.py` 中补了 warmup + cosine：

```ini
scheduler = cosine
warmup_fraction = 0.05
min_lr_fraction = 0.05
```

并把种子噪声同时降到 0（`gaussian_scale = 0.0`）——`t = 0` 时种子就是输入，
σ=0.05 的噪声是纯干扰：64 条事件的探针里，有噪声时只能拟合到 0.97 Å，无噪声到 0.49 Å。

## 二、不可约歧义：即使给了真值键变化也不够

用户判断"模型知道了末态的键位、方向的变化"就能到位。为此先实现了键变化条件
（`basinflow/geometry/bonds.py`，边上三分类 one-hot `{不变, 生成, 断裂}`，
见 doc 19 §六），再直接测量**这个条件到底携带多少信息**。

`tools/diagnose_bond_change_identifiability.py`，9000 条训练事件：

| 量 | 值 |
|---|---|
| 近同反应物对（对齐后 RMSD < 0.2 Å） | **8313** 对 |
| 其中**共享同一拓扑变化**的比例 | **9.8%**（813 对） |
| 同拓扑对的原始位移分歧（中位 / 均值） | 1.37 / 4.08 Å |
| 同拓扑对去掉刚体后的**化学**位移分歧（中位 / 均值） | **1.33 / 3.91 Å** |
| 异拓扑对的化学位移分歧（中位 / 均值） | 1.60 / 6.31 Å |

两点结论：

1. **条件确实有信息**：近同反应物里 90% 的事件拓扑变化不同，说明"哪些键断/成"
   正是区分它们的关键量——这与用户的判断一致，也是加条件的理由。
2. **但条件不足以定解**：在**反应物几何几乎相同、且拓扑变化完全相同**的 813 对里，
   所需位移仍相差 **1.33 Å（中位）**。两端相差 1.33 Å 时，任何单一确定性预测的
   误差下界约 `1.33/√2 ≈ 0.94 Å`。

配套的最近邻 oracle（`tools/diagnose_condition_ceiling.py`，用 benchmark 自己的
`movable_mic_rmsd` 打分）：

| 条件 | 匹配数 | RMSD 中位 / 均值 / 最小 |
|---|---|---|
| 仅反应物（同组成最近邻） | 535 / 536 | 4.81 / 6.06 / 0.56 |
| 反应物 + 拓扑变化 | 445 / 536 | **1.32** / 4.74 / **0.197** |

**这张表还有一个用处：它给出"给定同样条件的查表上界"。** C 臂训练完（60 轮）后
在全部 536 个 val basin 上的 raw 中位是 **0.645 Å**，**比拿到真值拓扑变化的
最近邻查表（1.32 Å）还低一半**。也就是说，剩下的这 0.6–0.7 Å 不是"模型太弱"，
而是数据本身在 `(R, 拓扑)` 这个条件下就没有更低的解。

而"什么都不做"（直接用 R 当 P）：

| 划分 | raw 均值 / 中位 | aligned 均值 / 中位 | `min(rmsd,1)` 均值 | aligned < 0.2 Å 的比例 |
|---|---|---|---|---|
| val (536) | 4.2144 / 1.0811 | 4.2144 / 1.0811 | 0.8998 | **0.0%** |
| test (537) | 4.6994 / 1.1280 | 4.6994 / 1.1280 | 0.9037 | **0.0%** |

**没有任何一个事件**的反应物与产物对齐后 RMSD < 0.2 Å。所以 0.1–0.2 Å 不是
"接近平凡解"的目标，而是要求几乎精确地预测产物——在 `(R, 拓扑)` 仍是一对多的
数据上做不到。

### 已排除的一条思路：oracle 活跃原子条件

一个自然的修补是"把真正移动的原子也告诉模型"。**实测无用，已放弃**（test 全量）：

| 原子类别 | 原子数 | 占比 | 真实 `|d|` 均值 | 模型误差 均值 / 中位 | 平方误差占比 |
|---|---|---|---|---|---|
| 活跃（`|d| > 0.1 Å`） | 7194 | **98.1%** | 4.298 | 1.157 / 0.548 | **100.0%** |
| 不活跃 | 137 | 1.9% | 0.048 | 0.082 / 0.050 | 0.0% |

98.1% 的可动原子本来就"活跃"，而模型对不活跃原子已经预测得足够准（0.082 Å）。
把真值活跃掩码当条件给模型，平方误差上限改善是 **0.0%**。
所以"补 active region"这条路线在这个数据集上不存在收益，误差全部落在
"预测大幅度位移"这件事本身。

### 条件的覆盖面本身也不完整

`transition1x_direct_t0_9000` 的 epoch-8 checkpoint，val 前 160 个 basin，
按"该原子是否参与任何键变化"拆分逐原子误差：

| 原子类别 | 原子数 | 逐原子误差 均值 / 中位 | 占总平方误差 |
|---|---|---|---|
| 参与键变化 | 556（32%） | 1.574 / 0.716 Å | **60.0%** |
| 不参与键变化 | 1159（68%） | 1.016 / 0.585 Å | 40.0% |

即：条件只描述 32% 的原子，剩下 68% 的原子**不参与任何键变化**却贡献了 40% 的
平方误差——那部分是构象弛豫，条件里根本没有它的信息。这也解释了为什么单靠
"补足键变化条件"不可能把 RMSD 压到 0.1 Å 量级。

（附带结论：位移尺度不需要后处理标定。对同一 checkpoint 扫描全局缩放
`α ∈ [0.8, 1.5]`，raw 均值在 `α = 1.0` 处最小（1.359 Å，`α=0.9` 1.443、
`α=1.1` 1.400），说明 L1 目标没有把预测整体压小。）

## 二之二、误差在哪里：29% 的"事件"根本不是局部事件

按每个 test 事件的 `|P - R|`（movable 原子的 RMS 位移）分桶，用 epoch 149 的 aligned RMSD：

| `|P-R|` / Å | 事件数 | 占比 | aligned 中位 | aligned 均值 |
|---|---|---|---|---|
| 0.3–0.6 | 29 | 5.4% | **0.152** | 0.195 |
| 0.6–1.0 | 193 | 35.9% | 0.333 | 0.388 |
| 1.0–2.0 | 156 | 29.1% | 0.643 | 0.664 |
| 2.0–3.0 | 3 | 0.6% | 1.098 | 1.100 |
| ≥ 3.0 | 156 | **29.1%** | 1.929 | 2.239 |

- `|P-R| < 1.0 Å` 的事件占 **41.3%**，但只贡献 **2.7%** 的总平方误差；
- `|P-R| ≥ 3 Å` 的事件占 **29.1%**，贡献 **91.4%** 的总平方误差。

**而这 29.1% 是什么？** 逐事件数键图的连通分量：

| 子集 | 事件数 | `|P-R|` 中位 | aligned 中位 | aligned 均值 |
|---|---|---|---|---|
| 全部 | 537 | 1.128 | 0.6277 | 0.9995 |
| **片段数保持不变** | **381（70.9%）** | 0.928 | **0.4287** | **0.4919** |
| 片段数改变 | 156（29.1%） | 13.797 | 1.9285 | 2.2393 |

`|P-R| ≥ 3 Å` 的事件里 **100%** 都是片段数改变的；反过来片段数改变的 156 条里
**28.9% 的产物是分离的碎片对**。这不是键感知的阈值问题——把共价半径系数从
1.3 扫到 1.5（MolGEN 用 1.5），多片段比例始终是 28.9%、保持不变。

也就是说：**Transition1x 里约 29% 的记录是"分子解离成两块、两块之间相距十几 Å"**，
它们既不是局部 KMC 事件，产物碎片的摆放也没有物理意义。把它们算进事件召回率
对 BasinFlow 的任务定义没有意义（AGENTS.md：`R_basin -> {P_k, TS_k, active_atoms_k,
direction_k}`，一个**局部**事件）。

因此新增评测口径 `--single-event-only`（`tools/evaluate_checkpoint.py`，
底层 `basinflow.geometry.bonds.preserves_fragments`）。它是**数据集范围决定**，
不是逐样本 oracle 挑选：对每个 basin 只读一次参考事件，所有对比臂删掉同一批 id。

### 单事件口径下的三档数字

| 划分 | n | aligned 中位 | aligned 均值 | `min(rmsd,1)` | < 0.2 Å | < 0.5 Å |
|---|---|---|---|---|---|---|
| **train** | 640 | **0.282** | 0.354 | — | **39.2%** | 79.2% |
| val | 402 | 0.434 | 0.482 | 0.503 | 16.7% | 59.2% |
| test | 381 | 0.431 | 0.491 | 0.504 | **20.5%** | 56.7% |
| test，什么都不做 | 381 | 0.928 | 0.979 | 0.864 | 0.0% | 2.1% |

相对"什么都不做"：**中位 −54%、均值 −50%**。

**误差被干净地拆成两半：**

1. **优化不足**：train 上还有 0.282 Å（39% 的事件已进 0.2 Å），而 64 条事件的探针
   在充分优化后能到 **0.138 Å**。这 0.28 → 0.14 的差距是纯优化。
2. **泛化/歧义**：train 0.282 → test 0.431 的 **1.53×**。这部分是 §二 的歧义。

两条加在一起解释了全部误差。**要冲 0.1–0.2 Å，必须先榨干第 1 项**——这正是
`transition1x_direct_t0_nonoise_cosine_9000` 在做的事。

## 二之四、【更正】"不可约歧义"的结论是错的：给定拓扑后目标唯一

我在 §二 得出的"`(R, 拓扑) → P` 一对多、存在 ~0.9 Å 下界"是**错误**的，
错在用什么当"拓扑签名"。§二 用的是**元素对**签名（如 `C-H:F`），
它把不同分子/不同构象上"同样是 C-H 成键"的事件混为一谈。
改用**原子索引级**的拓扑签名重测：

| 量 | 值 |
|---|---|
| 训练事件 | 9000 |
| 不同的（构象, 元素）组合 —— 用**旋转不变**的原子间距离矩阵做 key | **1182** |
| 每个构象平均对应的事件数 | 7.6（最多 33） |
| **同时共享构象与索引级拓扑的训练事件对** | **0** |

**没有一对训练事件共享"同一个构象 + 同一个拓扑"，因此不存在冲突目标**：
`(构象, 拓扑) → 产物` 在整个训练集上是一个**良定义的函数**。
此前看到的"近同反应物要求不同位移"全部由**不同的拓扑**解释，
而拓扑正是我们作为条件给出的那一项。

顺带把 val/test 也测了（同样旋转不变）：

| 划分 | n | 构象已在 train 出现 | **构象与拓扑都出现** | 该构象在 train 的副本数 |
|---|---|---|---|---|
| val | 536 | **99.4%** | **0.0%** | 中位 8 |
| test | 537 | **98.9%** | **0.0%** | 中位 9 |

即：**反应物构象全都见过（每个约 9 个副本），但每个副本的拓扑都不同，
test 自己的拓扑从未出现过。** 模型要学的是
"这样一组键变化对应多大位移"，而不是"这是哪个反应"——这**正是条件模型该做的事**。

**结论更正**：R→P 在给定拓扑条件下**没有信息下界，0.1–0.2 Å 原则可达**；
残差 0.43 Å 属于**优化/泛化**，不是数据歧义。这与三个探针一致：
64 事件 0.138 Å、128 事件（带方向）0.092–0.101 Å、train 单事件口径 0.282 Å / 39% 达标。
**唯一有效的动作就是把拟合做深**，也就是 240 轮续训在做的事。

（一句免责：拓扑签名用原子索引，若同一构象在不同事件里的原子顺序被置换过，
同一个化学拓扑会得到不同签名。抽样检查显示同一构象的 species 顺序一致，
但这条没有全量验证。）

## 二之三、test 的反应物在 train 里都有副本，但反应不同

把 test 的每个反应物与 train 里**同组成**的反应物做 Kabsch 对齐比较：

| 量 | 值 |
|---|---|
| test 单事件 basin 数 | 380 |
| 在 train 中找到对齐 RMSD < 0.05 Å 的反应物 | **372（98%）** |
| 最近邻反应物距离的中位数 | **0.000 Å**（即同一个构象，只差一个刚体旋转） |
| 最近邻距离与模型误差的相关性 | **−0.079**（几乎无关） |

也就是说：**test 的反应物几何在 train 里已经被见过 98%**，模型的 0.43 Å 误差
完全不是"没见过这个分子"。

那产品呢？对同一批 372 对，比较两者的产物（原子序一致，直接 Kabsch 对齐）：

| | 数量 | 模型 aligned 中位 |
|---|---|---|
| 产物也相同（< 0.05 Å） | **0** | — |
| **产物不同** | **372（100%）** | 0.4338 |
| 两者产物间距中位数 | **1.302 Å** | |
| 两者键变化标签相同的比例 | **0.0%** | |

**结论有三条，都很硬：**

1. **误差不是覆盖率问题**：反应物全都见过，最近邻距离中位 0.000 Å，
   且误差与最近邻距离几乎不相关（−0.079）。
2. **数据确实是多通道的**：同一个反应物构象在数据集里对应多个不同产物
   （间距 1.30 Å、拓扑变化 100% 不同），这与 §二 一致。
3. **但因为拓扑变化作为条件已经给出**，`(R, 拓扑)` 在 test 上仍然是可以从
   train 学到的映射；0.43 Å 的残差因此归到 §一之二的**优化/容量**，
   而不是不可约歧义。

顺带一个 benchmark 性质：该 split 不是按反应物分组的，反应物跨 train/test 泄漏
（对齐后 0.000 Å）。这让 benchmark 对"记住 R"的模型更友好，也再次说明
残差不是覆盖不足。

## 三、口径核对：0.1–0.2 Å 是怎么来的

doc 18 §八与 doc 20 §一已指出任务不同；本轮补充两个此前未记录的差异：

| | MolGEN / ReactOT | BasinFlow |
|---|---|---|
| 任务 | R+P → **TS** | R → **P** |
| 先验尺度 | `x0std = 1.0` | 0.05（本轮修复） |
| 主指标 | **Kabsch 对齐** + 原子置换匹配 + `min(rmsd,1)` | **不对齐** in-place raw RMSD |
| 报告值 | `val_meanRMSD_Kabsch` 0.129–0.161 | 见第六节 |

MolGEN 的 `rmsd_core`（`mdgen/equivariant_wrapper.py:47-70`）先做
`KabschMatcher.fit` 再取 RMSD，并在置换数 <1e4 时做原子置换枚举。
BasinFlow 的主指标是 `movable_mic_rmsd`，**不含任何对齐**。两者数值不可直接比较，
这是把"0.1–0.2 Å"当成 BasinFlow 目标时最主要的量纲错配。

## 四、可达到的目标与协议建议

在 R→P 口径下，可达目标应写成：

| 目标 | 口径 | 依据 |
|---|---|---|
| aligned 中位 ≤ 0.8 Å | Kabsch 对齐、movable、逐事件中位 | §二下界 ~0.94 Å 的确定性最优 |
| raw 均值 ≤ 1.0 Å | 现有 `movable_mic_rmsd` | 需同时压掉长尾（当前尾部把均值抬到 4.2） |
| 事件召回而非逐样本 RMSD | 生成候选经**弛豫**后是否落回真产物盆地 | AGENTS.md 的 basin-level 口径 |

逐样本 0.1–0.2 Å 只有在**任务变成 R+P→TS** 时才成立。若用户要的是与 MolGEN 可比的数字，
必须换任务，而不是继续调 R→P。

### 条件从哪来：可部署性问题

本轮所有达标的数字都用了 `bond_change_source = oracle`，即**真值拓扑变化**。
这是诊断上界，不是可部署结果。它能不能变成可部署的，取决于"事件能否从 R 预测出来"，
而 §二 已经给了否定答案：

- 8313 对"近同反应物"（对齐后 < 0.2 Å）里，只有 **9.8%** 共享同一拓扑变化。
  也就是说，**同一个反应物几何对应多种事件**，任何从 R 出发的事件分类器都有
  90% 的条件多义性。
- 这不是模型能力问题，而是 Transition1x 的构造：同一分子的不同 IRC 通道被分别收录。

因此可部署的正确接口是**把事件当作输入条件，由 KMC 侧的种子/其它物理先验提供**，
模型负责"给定事件生成几何"。本轮已经把这条接口做实（`EventSeed.bond_change`，
见 doc 19 §六），下一步要解决的是**谁来提供这个种子**，而不是把模型做得更大。

长尾必须在报告里单独拆开：val 有 **25%** 的事件 `|P - R| > 3 Å`（最大 23.2 Å），
这些事件主导了 raw 均值。`tools/summarize_benchmark.py` 与
`run_single_event_molecule_trials` 现已同时输出：

- `raw_rmsd_angstrom`（原口径）
- `aligned_rmsd_angstrom`（Kabsch，与参考可比）
- `clipped_raw_rmsd_angstrom`（`min(rmsd,1)`，与参考同口径）
- `best_of_trials`（逐 basin 最优候选，**用真值选**，标注为 oracle 上界）

| C 120 轮（val） | 11.9% | 43.7% | 71.8% | 8.8% |
| C 120 轮（test） | 12.5% | 41.5% | 67.8% | 9.1% |
| C 60 轮（val） | 8.6% | 39.0% | 70.5% | 7.3% |
| C 去掉条件（val） | **0.0%** | 1.3% | 45.7% | 25.0% |
| 什么都不做（val） | **0.0%** | — | — | 25.0% |

读法：

1. **条件的作用是决定性的**：同一 checkpoint，给真值键变化把 raw 中位从 1.068 压到
   0.645、把落在 0.2 Å 内的 basin 从 **0% 抬到 8.6%**、把长尾从 25.0% 压到 7.3%。
   用户的判断（"模型知道了末态的键位变化就能到位"）在**方向上被证实**。
2. **但绝对水平仍差 3 倍**：中位 0.57–0.63 Å，目标是 0.1–0.2 Å；只有约 13% 的
   basin 达标。原因见 §二：`(R, 拓扑)` 一对多，且条件只覆盖 32% 的原子。
3. **B 臂（σ=1.0，保留流式采样）明显弱于 C 臂**，见下表；说明"恢复 MolGEN 先验"
   只解决了退化，没有解决任务本身。

**B 臂（σ=1.0，MolGEN 先验，50 步 Euler）同一口径：**

| 划分 | n | raw 均值 / 中位 | aligned 均值 / 中位 | `min(rmsd,1)` 均值 | aligned < 0.2 Å | raw > 3 Å |
|---|---|---|---|---|---|---|
| val | 536 | 1.6520 / 0.8744 | 1.3744 / 0.8144 | 0.7570 | 5.4% | 12.1% |
| test | 537 | 1.5574 / 0.9192 | 1.2446 / 0.8565 | 0.7630 | 5.2% | 13.0% |
| val，去掉条件 | 536 | 4.2518 / 1.1274 | 4.2437 / 1.1213 | 0.9106 | 0.0% | 25.0% |

B 比"什么都不做"好，但每一项都劣于 C：中位高 0.19 Å、`min(rmsd,1)` 高 0.10 Å、
达标率 5.4% 对 8.6%。**恢复 MolGEN 的先验尺度只解决了 §一 的退化（让场重新有方向），
没有解决 §二 的歧义**——后者是任务本身的性质。

### 训练集上已经达标：中位 0.1997 Å，50.2% 落在 0.1–0.2 Å 内

方向臂（80 轮）在**训练集**单事件口径上的表现（512 个 basin）：

| 口径 | aligned 中位 | aligned 均值 | < 0.2 Å | < 0.5 Å |
|---|---|---|---|---|
| **train** | **0.1997** | 0.3026 | **50.2%** | 83.0% |
| test | 0.4143 | 0.4983 | 21.3% | 58.0% |

即：**模型在见过的数据上已经打进 0.1–0.2 Å 目标区间**（中位 0.1997、一半事件达标），
train/test 之比 2.07×。

### 它还在"拟合中"，不是过拟合

同一条臂在训练集上的中位误差随轮数单调下降：

| epoch | 20 | 40 | 60 |
|---|---|---|---|
| train aligned 中位（256 basin） | 0.3263 | 0.2646 | 0.1900 |

训练误差**仍在下降**而不是回升，所以这是**欠拟合 + 泛化间隙**的组合，
不是过拟合。**继续训练确实是有效杠杆**，240 轮续训正是针对它。

### 已确认：径向基范围（cutoff）被设得过宽（正结果）

一个此前从未检查的超参数：`r_max = 12`。对 ~15 个原子的分子，**6 Å 就已经全连接**
（`r_max=6` 与 `12` 每分子都是 291 条边），所以把 cutoff 从 6 拉到 12 **只让距离编码变粗**：
96 个 Bessel 基在 12 Å 上是 0.125 Å 间距，在 4 Å 上是 0.042 Å。

128 事件、400 epoch、lr 3e-3、同一 seed：

| `r_max` | 每分子边数 | train aligned 中位 | **均值** | L1 |
|---|---|---|---|---|
| 12 Å | 291 | 0.0982 | 0.3091 | 0.1507 |
| 6 Å | 291 | 0.1399 | 0.2424 | 0.2112 |
| **4 Å** | 223 | **0.0795** | **0.1742** | **0.1237** |

**均值改善 44%**（难事件受益最大），中位改善 19%。键变化边都在 2.5 Å 内，
**永远落在 4 Å 图里**，所以条件不受影响。已按 `r_max = 4` 排一条完整的 R→P 臂。

（注意：6 Å 比 12 和 4 都差，说明单 seed 探针有噪声；12 → 4 的**均值**差距很大，
但仍然需要在完整训练里确认。）

### 已排除：把键变化汇总到节点上（负结果）

一个自然的假设是"条件只落在约 3% 的边上，标量滤波看到的是大海捞针"，
于是把每个原子自己的**成键/断键计数**直接加到节点特征上（`bond_change_summary`，
flag 门控、不破坏既有 checkpoint）。128 事件探针（400 epoch、lr 3e-3）：

| 臂 | 训练 aligned 中位 | 末步 L1 |
|---|---|---|
| 方向条件 | 0.9111 → **0.0728** | 0.1095 |
| + 节点汇总 | 0.9141 → **0.0753** | 0.1130 |

**没有收益**（基线还略好），假设不成立：模型本来就能从稀疏的边条件里读到信息。
该开关已按"放弃冗余部分"的原则**回退**，不留在代码里。

同时这条探针给了一个有用刻度：**在 128 条事件上、同等优化下，方向臂能拟合到 0.0728 Å**
——远在 0.1–0.2 Å 目标之内，说明架构与条件表达都不是瓶颈。

### 误差解剖：均匀的精度上限，不是"条件覆盖不到"

epoch-80 方向臂，test 单事件口径，按原子是否参与键变化拆分：

| 原子类别 | 原子数 | 占比 | 逐原子误差 均值 / 中位 | 平方误差占比 |
|---|---|---|---|---|
| 参与键变化 | 1293 | 25.7% | 0.4557 / **0.2925** | 27.9% |
| 不参与键变化 | 3745 | 74.3% | 0.4526 / **0.2779** | **72.1%** |

**两类原子的逐原子精度几乎完全一样（0.29 vs 0.28 Å）**。不参与键变化的原子占平方误差多，
只是因为它们数量多 3 倍。这不是"反应原子预测不准"，而是**一个均匀的精度上限**——
要压低中位就必须把所有原子的精度整体提高 2 倍。

逐 basin 分布（381 个）：

| 阈值 | < 0.1 Å | < 0.2 Å | < 0.3 Å | < 0.5 Å | < 0.8 Å |
|---|---|---|---|---|---|
| 占比 | 7.9% | **21.3%** | 37.0% | 58.0% | 83.7% |

最差的 22 个 basin（5.8%）承担 50% 的平方误差，最差 20% 承担 73.8%——
长尾主导均值，而中位数由整体的均匀精度决定。

### 是欠拟合，不是记忆，也不是过拟合

- 训练集中位 **0.1997**，而 128 事件探针能把同类结构拟合到 **0.09**；
  256×6（4M 参数）对 9000 个样本完全够"背下来"，但训练误差停在 0.20 ⇒ **没有在记忆**。
- 训练误差随轮数仍在下降（0.326 → 0.265 → 0.190）⇒ **欠拟合**。
- 因此**正则化是反向的**（会加重欠拟合），**容量与优化才是杠杆**。

这直接支持两个已排队的动作：R→P 方向臂续训到 240 轮，以及把 backbone 放大到
384×8 的容量对照。

### 误差与"拓扑有多新"无关

对每个 test 单事件，找同一构象在 train 里的副本，算拓扑签名的对称差
（差几个键变化），再分桶看模型误差：

| 拓扑对称差 | n | aligned 中位 |
|---|---|---|
| 0–2（最接近训练） | 13 | 0.278 |
| 2–4 | 205 | 0.429 |
| 4–6 | 152 | 0.407 |
| 6–9（最新） | 7 | 0.600 |

相关系数 **−0.019**。误差**不随拓扑新颖度增长**——说明瓶颈不是"没见过这种拓扑"，
而是映射本身还没拟合到位。这与上一节一致。

### 三条 R→P 臂的终点对比（同一 80 轮预算，全量 val/test）

| 划分/口径 | 无噪声 + cosine（标签条件） | **+ 键变化方向** |
|---|---|---|
| val 全部 | 0.5677 / 0.6217 / 14.2% | 0.5784 / **0.6183** / **15.5%** |
| val 单事件 | 0.4314 / 0.4973 / 18.9% | **0.4312 / 0.4911 / 20.6%** |
| test 全部 | 0.6197 / 0.6470 / 15.3% | **0.6002 / 0.6384** / 15.1% |
| test 单事件 | 0.4339 / 0.5028 / 21.5% | **0.4143 / 0.4913** / 21.3% |

（每格：aligned 中位 / `min(rmsd,1)` 均值 / < 0.2 Å 比例）

方向条件在**每一项上都略微更好**（test 单事件中位 −4.5%、截断均值 −2.3%），
与逐 epoch 配对统计（17–26/30 轮更优）一致。两条臂都远优于"什么都不做"
（val 全部中位 1.0811、截断 0.8998）。

### 再训 60 轮的边际增益

C 臂训到第 60 轮后从该 checkpoint 续训到第 120 轮（`transition1x_direct_t0_9000_cont`，
同数据、同优化器、同损失，累计 16920 步）。下面全部来自 128 个 val basin 的同一子集，
可比：

| checkpoint | `min(rmsd,1)` 均值 | raw 中位 | aligned 中位 |
|---|---|---|---|
| epoch 53 | 0.5808 | 0.532 | 0.490 |
| epoch 60 | 0.5802 | 0.525 | 0.490 |
| epoch 95 | 0.5656 | 0.512 | 0.468 |
| epoch 106 | 0.5649 | 0.513 | 0.464 |

**60 → 106 轮（翻倍）只换来 ~2.6% / 3.4% / 5.3%。** 在**全量** val/test 上，
60 → 120 轮仍带来可见改善（aligned 中位 val 0.6212 → 0.5716、test 0.6636 → 0.6312；
达标率 val 8.6% → 11.9%、test 9.1% → 12.5%），但 **120 → 149 轮完全停止**
（见上表，两行互有胜负）。训练 L1 从 0.388 一路降到 0.170，RMSD 却只动了几个百分点——
继续下降的损失落在 §二 那 25% 无法解出的事件上。
**不能再用训练损失判断这条臂是否还有救；epoch 120 之后它就到底了。**

### 曲线（128 个 val basin 的逐 epoch checkpoint）

C 臂的 `rmsd_curve/rmsd_curve.csv`（每 5 轮抽一行）：

| epoch | raw 均值 / 中位 | `min(rmsd,1)` 均值 | aligned 中位 |
|---|---|---|---|
| 1 | 3.861 / 0.855 | 0.7764 | 0.838 |
| 11 | 1.228 / 0.701 | 0.6946 | 0.662 |
| 21 | 1.216 / 0.604 | 0.6387 | 0.569 |
| 31 | 1.204 / 0.564 | 0.6131 | 0.514 |
| 41 | 1.181 / 0.554 | 0.5916 | 0.490 |
| 51 | 1.071 / 0.531 | 0.5869 | 0.497 |
| 60 | — | 见上表（全量） | — |

两点：

- **25 轮后基本收敛**：raw 中位从 0.604（21 轮）到 0.531（51 轮）只降 12%，
  `min(rmsd,1)` 从 0.6387 到 0.5869 只降 8%。再堆轮数收益递减。
- **损失与 RMSD 解耦**：训练 L1 从 1.395 一路降到 0.388（60 轮），但 RMSD 早就平了。
  继续下降的损失来自 `|P - R| > 3 Å` 的那 25% 事件（§二），它们本来就不可能在

### 条件消融（逐 epoch）

| checkpoint | raw 中位（oracle 条件） | raw 中位（去掉条件） | 差 |
|---|---|---|---|
| epoch 2 | 1.2834 | 0.9475 | **−0.34（条件反而更差）** |
| epoch 11 | 0.7241 | 0.9900 | +0.27（条件更好） |
| epoch 60（全量 val） | 0.6451 | 1.0678 | **+0.42（条件更好）** |

**早期条件会拖后腿，后期才起作用。** epoch 2 上"全不变"的建议让模型少动、反而更接近
"什么都不做"；随着训练，模型学会把拓扑变化翻译成位移，条件的价值才显现。
这条曲线同时解释了为什么单看前几轮的消融会得出"条件没用"的错误结论。
